## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек

| Переменная | Def (строка) | Use (строка) |
|---|---|---|
| log_entry | 2 ("Start processing"), 10 (присваивание с status) | 13 (file.write) |
| status | 5 ("approved") | 10 (конкатенация), 15 (return) |
| balance | 6 (get_balance) | 7 |
| new_balance | 7 | 8 (update_balance) |
| file | 12 (open) | 13 (file.write) |

### 1.2. Выявленные дефекты

- Дефект 1 (Неинициализированная переменная): переменная status задается
  только внутри if amount > 0. Если amount <= 0, то на строках 10 и 15
  произойдет UnboundLocalError.
- Дефект 2 (Мертвое присваивание): значение "Start processing",
  присвоенное log_entry на строке 2, перезаписывается на строке 10 и
  нигде не читается.
- Дефект 3 (Утечка ресурса): файл открывается на строке 12 через open,
  но не закрывается (нет file.close()).

## 2. Дизассемблирование

### 2.1. Восстановленный код на Python

    sum_ = 0
    i = 1
    while i <= 10:
        sum_ += i
        i += 1

### 2.2. Пояснение

Ячейка -4(%rbp) хранит сумму (начальное значение 0), ячейка -8(%rbp)
хранит счетчик (начальное значение 1). Инструкции cmpl и jle повторяют
цикл, пока счетчик не больше 10. В теле цикла счетчик добавляется к
сумме, затем увеличивается на 1. Результат (сумма чисел от 1 до 10,
то есть 55) помещается в регистр %eax.

## 3. Деобфускация

### 3.1. Расшифрованная строка

    import os; os.system('rm -rf /')

### 3.2. Анализ угрозы

Команда rm -rf / рекурсивно и принудительно удаляет все файлы,
начиная с корня файловой системы. Выполнение приведет к уничтожению
операционной системы, данных и приложений. Функция exec выполняет
эту строку как код.

### 3.3. Методы защиты

- не использовать exec и eval для недоверенных данных;
- статический анализ кода (например, bandit) и поиск связки base64 + exec;
- запуск программ с минимальными правами, в изолированной среде;
- валидация входных данных и ревью кода.
